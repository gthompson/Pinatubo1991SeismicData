# Reviewed-window metric schema

Schema version: `pinatubo-notebooks-1`. One row is one accepted noise or event interval from one trace. Identity is `(record_id, trace_index, window)`; duplicate channel IDs in a file remain distinct. The machine-readable schema is generated by `analysis_workflow.schema_table()` and exported by notebook 30. `metric_provenance.json` records parameters, feature version, review hash and preprocessing. Undefined values are NaN, never silently substituted with zero.

| Column family | Units and definition |
|---|---|
| Identity/provenance | File, trace key/ID/index, recorded start, provisional gain epoch and nominal attenuation |
| `window_*`, `actual_*` | Half-open file-relative seconds, selected sample count and support duration |
| `amplitude.*` | FLOVOpy RMS, mean absolute, absolute peak, peak-to-peak and standard deviation in counts; skewness and excess kurtosis dimensionless; sum(x²)/fs in count² s, not joules |
| `sam.*` | FLOVOpy bandpassed mean absolute counts in LF, HF and full bands; log2(HF/LF) ratio |
| `sem.*` | FLOVOpy bandpassed sum(x²)/fs in count² s and log2(HF/LF) ratio |
| `psd.*` | Hann-Welch full-grid peak/centroid/bandwidth (Hz), configured band-integrated powers (count²) and log2(HF/LF) |
| `feature.*` | FLOVOpy `core.features` v1 schema: time-energy shape, periodogram power shape/frequency/flatness, cepstrum and full/LF/HF timing/cross-band descriptors |
| `event_to_noise_rms_*` | Paired event/noise RMS ratio; 20 log10(ratio) dB; absent for unpaired/invalid rows |
| `artifact_pre_*`, `artifact_post_*` | Original-window/processed-window 40.5-Hz PSD peak, ratio, power fraction, test status and tri-state detection |
| `metric_status`, `metric_flags`, `feature_flags` | Processing state and retained QC flags; they are not classification labels |

All metrics use uncalibrated counts; StationXML has no complete electronics response. A provisional epoch match uses recorded time and is not proof that the gain was known at that instant. Do not pool across station/channel/gain epochs or clipping states without justification.

## Processing and temporal interpretation

Select actual sample centres within `[start,end)`. Do not pad, interpolate, silently compress gaps or include the sample at `end`. Actual support is from the first selected sample to the grid boundary following the last selected sample; that boundary may extend by less than one sample beyond the requested endpoint, while no selected sample centre does. Missing samples reject that window's measurements. All current transforms act on copies.

Each selected window is linearly detrended. An optional lowpass, off by default, is applied independently to that window; inspect boundary effects if enabled. FLOVOpy ampengfft additionally detrends its copy. Features are computed from the same detrended input with their documented mean removal and band filters. Amplitude/SAM/SEM are reused from FLOVOpy; peak-to-peak and absolute summaries have their direct sample definitions. The legacy `temporal_features.py` is not called.

SAM/SEM bands use FLOVOpy's zero-phase, two-corner filtering. Band summaries are masked when the window does not satisfy a conservative two-sided edge-support criterion of two cycles per edge. A five-second window is too short for the default LF band at 0.8 Hz under that policy. This is deliberately different from a Fourier band-power estimate, which remains a valid finite-window descriptor with its own limited resolution. Short/unreliable filtered features do not become zero.

Feature timings are seconds from the selected window start. Energy quantile spans describe that finite window, not necessarily the physical event/coda duration. Noise-only metrics do not compare noise to itself: threshold-onset/SNR features requiring an external reference remain missing. Event features may use the paired accepted noise reference. Truncation, low SNR, filter edges and short-band limitations retain FLOVOpy flags. No automatic coda-end inference is made.

`feature.spectral_power.*` uses FLOVOpy's Hann periodogram, while `psd.*` uses matched Hann-Welch estimates. Their distinct names prevent conflating estimators. Frequency moments use the full DC–Nyquist grid unless a band is named; a narrowband acquisition artifact can influence them. Shape/entropy features are dimensionless except spectral centroid/spread (Hz), cepstral centroid/spread/quefrency (s) and rates (s⁻¹).

## PSD comparisons

Welch and equal-weight DPSS use the same actual segment length, FFT grid and temporal step for both windows in a pair. Shorter windows can reduce the common segment length; actual duration and segment count are saved. Segment counts differ for unequal window lengths, so estimator variance also differs. DPSS smoothing bandwidth is distinct from FFT bin spacing. There is no zero-padding or claim of added information from overlap.

The narrowband screen uses a 38–43 Hz search and a 33.5–47.5 Hz background excluding ±3 Hz around 40.5. Ratios ≥10 are flagged. Invalid/Nyquist-limited/resolution-limited tests have missing `detected`, not false. No instrument origin is assigned, and filtered suppression is not absence in the source.

Preceding noise is conditioned on an event having triggered and been retained. These metrics are not an unbiased ambient-noise survey, network detection threshold, calibrated motion, earthquake magnitude or absolute timing correction.

## Full persistence schema

The fixed columns above remain the plotting view, not a whitelist for preservation. Complete event results now live in EnhancedEvent JSON sidecars selected by `event_metrics_index.csv`. Each `traces` entry identifies one original trace index and accepted window, and includes `summary` (the curated row), `enhancedstream` (every original metrics/spectral/spectrum key plus station summaries and processing), `features` (all values, flags and provenance), `psd` (frequency grids, Welch/DPSS arrays and estimator settings) and `artifacts` (both audits). Full original computed values are retained for audit; use the curated masks/flags when short filtered bands are unreliable.

`all_window_metrics.csv` is EnhancedCatalog's dynamic full export: all nested keys become columns and all arrays/lists are encoded as complete JSON cells. It includes future fields automatically. `all_metrics_schema.csv` lists the actual exported columns/dtypes. `events_metadata.csv` is a complete event-level enhanced-metadata export. JSON is authoritative, with NaN/infinity represented as null, and arrays preserved numerically. The existing summary CSV is a conventional event metadata view, while QuakeML carries actual core event fields only. No complete electronics calibration or fictitious origin is introduced.

## Automatic-policy provenance

`window_policy` is fixed/detected/reviewed; `window_selection_method` distinguishes fixed, detected, fixed fallback and manual decisions. `window_flags` records unresolved detections and other selection limitations. `event_end_rule` and `event_end_record_limited` identify record-end event-data windows; they do not assert that a physical coda was measured. Automatic windows are not labelled human accepted.

For fixed mode, noise is exactly `[trace start, trace start+5 s)` and event is `[trace start+5 s, record end)`. The manual/detected one-second guard is not subtracted from this fixed five-second window. Detected mode applies its guard to onset-based selections and uses only the explicitly configured fallback. Policy, actual bounds and code identity enter each event's computation signature. Automatic results are independent of unrelated manual-review edits.
